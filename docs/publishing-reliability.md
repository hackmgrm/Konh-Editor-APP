## 操作入口

- 顶栏 **AI 排版**：生成候选 → 左右预览及文字对照 → 采用此排版。可以切换历史候选。
- **文章管理 → 本机完整快照**：查看占用、离线预览、导出 HTML 或逐份清理。
- **推草稿 / 文章管理 → 推送记录与快照**：核对不确定的提交，确认远端结果后解除拦截。

## 数据与清理

快照位于 Tauri `app_data_dir()/article-assets/<快照编号>/`，图片不进入配置 JSON。macOS 的位置通常是 `~/Library/Application Support/com.konheditor.app/article-assets/`。每份快照上限 100 MB、200 个图片资源；写入临时目录完成后才变为可见快照，既有快照不能覆盖。

离线 HTML 内嵌图片，无需依赖原图床；预览与导出禁止脚本和外部资源加载。`submitted.html` 保留本次准备发送给微信的正文，微信后台可能进一步处理图片与样式。保存成功不等于远端提交成功，需结合推送状态判断。

没有自动删除资产：用户在文章管理中逐份清理。文字推送记录保留最近 50 条普通记录及所有待核对记录；完整资产单独保留，直到手动清理。旧版文字快照无法追溯恢复当时的图片字节。原文、候选、发布 HTML 可能包含文章本身的私人内容，应随本机数据一起备份。

身份映射保存在本机配置，兼容旧文章记录。范围是应用内自动/手动改名及目录移动；应用外移动、拷贝整个工作区到另一台机器的身份迁移尚不自动判断，避免把两篇相似文章关联到同一个公众号草稿。

## 本机验证

最终结果：50 项前端测试、51 项 Rust 测试全部通过，生产构建通过。保留既有 chunk 体积提示与旧 Agent 未使用代码警告。

- `npm run test:publishing`：发布、身份与排版状态回归。
- `node --experimental-strip-types --test src/*.test.ts src/store/*.test.ts`：全部前端单元测试。
- `npm run build`：类型检查与生产构建。
- `cd src-tauri && cargo test --lib`：本机配置、快照文件、模型结果解析及工作区文件操作。
- ego-browser + 临时 React/Tauri IPC 模拟页面：采用前不修改原稿、交错请求、原文变化、身份迁移与中断恢复、图片内嵌导出及已采用快照保护。
- 实际发布服务模拟调用顺序为：准备记录 → 图片资产保存 → 提交标记 → 草稿请求 → 完成记录。保存的 `submitted.html` 与请求正文一致，回执指向对应资产编号。

## 尚待真实环境验收

没有使用真实公众号创建、更新或正式发布，也没有把构建测试当成 Windows/Linux 实机验收。需要专用测试公众号及对应机器后，按以下流程执行：

1. 使用同图分别推送 A/B 测试号，核对各自素材与草稿编号；切回 A 更新，确认原封面、摘要及 B 草稿不受影响。
2. 提交后模拟断网，检查重开后的待核对状态；对照后台实际结果，选择续接或重新创建，确认没有重复草稿。
3. 在 Windows/Linux 启动构建产物，验收原生确认、文件改名/移动、离线 HTML 导出、快照删除及主题恢复。
4. 上述真实验收完成后再用于正式版本发布。当前本机安装包只代表 macOS 本机构建验证。
