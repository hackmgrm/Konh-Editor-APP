# 统一备份与恢复

设置页「备份同步 → 统一备份与恢复」是本应用唯一的完整备份入口。它把写作工作区、手帐数据、日记图片和文章素材写进一个带清单的文件夹，并能在需要时把它们读回来。

这不是同步功能。WebDAV 同步是持续的双向分类同步；统一备份是一个时间点的手工归档。两者互不替代，区别见文末。

## 备份里有什么

| 分节 | 内容 | 来源 |
| --- | --- | --- |
| `workspace` | 你选择的写作工作区文件：`.md`、`.markdown`、`.txt`、图片和其他用户文件，含空目录和中文文件名 | 用户选择的工作区目录 |
| `planner` | 任务、日记、专注记录、习惯、便签、倒计时、时间块 | `tongyun_planner.db` 白名单表 |
| `journalImages` | 日记图片 | IndexedDB `tongyun_journal_images` |
| `writingArtifacts` | 文章素材、文章关联数据与自定义主题 | `article-assets`、`themes` |

手帐只导出白名单里的七张表，并且导出每一列——包括 `repositories.ts` 写进 `data` 列的完整对象 JSON，所以自定义字段不会丢。

`workspace/` 里不会写入 macOS 的资源分叉文件和 Finder 垃圾：`.DS_Store`、所有 `._*` 在扫描时就被跳过，恢复时也不会被写回。

## 备份里没有的东西

凭据一律不出现在归档里，恢复后需要重新填写：

- 微信 AppSecret、公众号 Token
- AI API Key、Jina Key、Cloudinary Secret
- WebDAV 密码、SMTP 密码、Google OAuth Token
- 系统钥匙串内容、远程 DSN 密码

还有几类数据刻意不备份：`user_prefs` 等设置表、`agents`、`task_dispatch`、`sync_outbox`、`sync_state`、同步冲突状态、设备锁和运行时状态。原因很直接——把同步队列恢复回去等于让旧状态覆盖线上，把设备锁恢复回去会让新设备打不开。

备份**不加密**。归档里有你的全部笔记和图片，请放在你自己控制的磁盘或加密卷里。

## 归档结构

```
konh-backup/
├── manifest.json
├── README.txt
├── workspace/          文件、空目录
├── planner/
│   ├── planner.json    七张表的完整行
│   ├── journal-images.json
│   └── attachments/
└── writing/
    ├── article-assets/
    ├── themes/
    └── metadata.json
```

`manifest.json` 至少包含：`format: "konh-unified-backup"`、`formatVersion: 1`、`createdAt`、`appVersion`、`sections`（含 `secrets: false`）、`fileCount`、`totalSize`，以及每个文件或目录的 `path` / `kind` / `size` / `sha256`。

## 写入端做了什么

1. 先取 Rust 维护锁（`src-tauri/src/write_gate.rs`），有窗口正在写就返回 `E_GATE_BUSY`，绝不并发写。
2. 同时升起前端维护标记（`src/tongyun/utils/maintenanceLock.ts`）。这是补齐的另一半：手帐的 SQL 写入走 Tauri SQL 插件，直接从 webview 发到 SQLite，绕过了 Rust 锁。标记会广播到所有窗口，期间每个 `Database.execute` 都被 `withMaintenanceWriteLock` 拒绝（`E_WRITE_PAUSED`），只读的 `select` 不受影响。标记带 30 分钟有效期，窗口关掉或进程崩了都不会把应用永久锁死。
3. 等待前端延迟落盘队列排空（`drainPendingStorage()`）。
4. 在一个隐藏的暂存目录里组装归档，逐文件流式算 SHA-256。
5. 复制工作区前后各扫描一次：路径、大小、修改时间、哈希。中途任何文件变了，本次备份直接失败，暂存目录删除，不发布。
6. 校验通过后用不改名的原子重命名发布。目标已存在时返回 `E_BACKUP_EXISTS`，绝不覆盖已有备份。
7. 最后释放维护标记与维护锁，并把维护期间被挡下的 localStorage 镜像重写一次，无论成功失败。

限额：20 万条目、单文件 1 GiB、总量 8 GiB、路径深度 64。路径逐段校验：拒绝绝对路径、`..`、反斜杠、Windows 保留名（`CON`、`NUL`、`COM1`…）、尾随空格或点、控制字符。符号链接、特殊文件、大小写冲突路径、重复路径一律拒绝。

外部编辑器改文件这件事，应用锁不住。所以做法不是假装锁住了，而是在复制前后各量一次，变了就失败——不会产生"看起来成功"的坏备份。

## 恢复

### 手帐：原地恢复，带回滚点

顺序是固定的：

1. 暂停 WebDAV 同步并等待写入队列排空。
2. 取维护锁并升起维护标记，恢复期间所有写入（Rust 的与 webview 直接发 SQL 的）都被拒绝。
3. 等已经开始的守护写入落地（`waitForMaintenanceWrites()`），再动表。
4. 把当前手帐导出成回滚点，落在应用数据目录的 `rollback/` 下。
5. 先在内存里校验日记图片 JSON，再清空 IndexedDB 重写，逐条核对数量与字节。
6. 在一个 SQLite 事务里整表替换七张手帐表，任何一步失败整体回滚。
7. 成功后才刷新界面：窗口会在 600 毫秒后重新载入，所有内存副本一起换成恢复后的数据。交给同步的那次暂停不会在提交后解除，只有重新载入才解除——所以恢复出来的表不会被紧接着的一次拉取覆盖。

失败时当前数据不变，回滚点保留，界面显示具体错误。

`rollback/` 里是同样格式的 `planner.json` 加一份 `rollback.json`。它不是一个可以点的按钮，但可以用同一套恢复流程读回来——测试里就是这么验证回滚的。

### 写作：默认恢复到一个新目录

默认目标是 `Konh恢复-YYYYMMDD-HHmm` 这样的新目录，不会默认写回你原来的工作区。两种策略：

- `new-only`：目标必须不存在或不含冲突，适合恢复到全新目录。
- `keep-current`：同名文件保留当前版本，备份版本另存为 `文件名 (备份 1).md`，并把冲突列表返回给界面显示。

不静默覆盖是硬规则：目标里已有的同名文件永远不会被悄悄替换。

`writing` 分节只能恢复文章素材和自定义主题到应用数据目录，它不碰你的工作区文件——工作区在 `workspace` 分节里。

## 恢复失败时会发生什么

- 校验失败的归档在写入任何目标之前就被拒绝：清单缺失、格式不对、版本不支持、大小不符、哈希不符、有多余文件，都会列进问题清单。
- 手帐恢复失败：事务回滚，旧数据可用，回滚点保留。
- 写作恢复失败：已写入的文件留在新目录里，你原来的工作区没被改动。
- 任何情况下都不会出现"恢复了一半还算成功"。

## 与 WebDAV 同步的区别

| | 统一备份 | WebDAV 同步 |
| --- | --- | --- |
| 触发 | 手动，一次性 | 持续，双向 |
| 范围 | 工作区 + 手帐 + 图片 + 素材 | 手帐七个分类 |
| 写作文件 | 包含 | 不包含 |
| 凭据 | 永远排除 | 有单独的密钥同步开关 |
| 冲突 | 不合并，保留两份 | 逐条合并或报冲突 |
| 用途 | 换机、归档、误删找回 | 多设备保持一致 |

恢复手帐时会暂停同步，避免刚恢复的数据被云端旧快照写回去。这次暂停不会在提交后自动解除：窗口重新载入时暂停计数归零，同步才按你的设置继续。如果不想让它立刻开始，先在「设置 → 备份同步」里关掉自动同步，确认数据没问题后再开回来。

## 验收范围

已经自动化验证的（`cargo test --locked` 与 `npx vitest run`）：

- 清单生成、逐文件 SHA-256、篡改检测、多余文件检测
- 完整导出与写作恢复到新目录，含空目录和中文文件名
- 手帐整表替换、回滚点生成与读回
- 同名文件冲突时保留当前版本并另存备份版本
- 非法路径、符号链接、大小写冲突、重复路径被拒绝
- 备份期间文件被外部修改导致失败且不发布
- 凭据与同步队列不出现在归档的任何一个文件里
- 日记图片流式写入与读回
- 一个在临时目录里跑完整链路的隔离场景测试

**尚未声明通过的**：

- 真实坚果云账号上的完整往返验收。自动化测试用本地目录模拟 WebDAV，没有连真实云端。
- Windows 桌面实机的手工验收。Windows 安装包由 GitHub Actions 的 `windows-latest` 构建（编译、测试、NSIS 打包、产物大小检查），但安装、运行、备份恢复到 Windows 目录仍需在真机上做一次。

## 不发签名证书

Windows 安装包**没有代码签名**。首次运行会被 SmartScreen 拦一次，选「更多信息 → 仍要运行」。release 工作流使用 `tauri build --no-sign`。
